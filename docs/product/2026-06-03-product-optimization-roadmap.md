# Toss 产品优化路线图

**更新时间：** 2026-06-03

**目标：** 把 Toss 从“能传、够轻”的浏览器传输工具，升级成“用户敢用、愿意常用、弱网也能用”的跨设备传输产品。

**现状判断：**
- 当前版本已经具备不错的产品底座：WebRTC P2P、端到端加密、会话指纹、PWA、Web Share Target、剪贴板发送、连接质量展示。
- 当前版本的主要短板，不在“能不能传”，而在“用户是否敢用”“高频场景是否顺手”“复杂网络下是否稳定”。
- 后续优化应优先围绕信任建立、重复使用体验、复杂网络兜底展开。

## 路线图原则

1. 先补信任，再补效率，最后补生态深度。
2. 优先做能显著提升留存和口碑的能力。
3. 保持 Toss 的核心差异化：零安装、轻启动、浏览器即用。

## P0：先修认知与定位

**周期：** 1 到 2 周

**目标：** 校准安全与连接表述，避免产品承诺和实际实现之间出现认知偏差。

**要解决的问题：**
- 用户容易把“内容不经过服务器存储”理解成“完全不依赖任何服务器”。
- README 与界面文案对“内容直传”“信令建链”“连接中转”的边界描述还不够清晰。
- 当前产品在信任表达上已有会话指纹和加密状态，但没有把这些信息组织成统一的话术。

**交付内容：**
- 重写 README 中的功能描述与安全说明。
- 在首页/状态区明确区分：
  - 传输内容是否端到端加密
  - 传输内容是否经过服务器存储
  - 建立连接时是否依赖信令服务
  - 当前连接是否为直连、穿透或中转
- 统一“局域网直传”“P2P 直传”“服务器中转”等术语的使用方式。

**验收标准：**
- README 与应用内文案对安全边界的表达保持一致。
- 用户首次阅读后，能分清“内容传输链路”和“连接建立链路”是两件事。
- 不再使用可能被理解为“完全无服务端依赖”的模糊表述。

## P1：建立接收信任链路

**周期：** 1 到 1.5 个月

**目标：** 让用户从“能连上”升级到“敢接收”。

**重点能力：**
- 接收前确认：接收方明确选择接受或拒绝。
- 更完整的对端身份信息：
  - 设备名
  - 会话指纹
  - 本次发送内容摘要
- 可信设备机制：
  - 记住此设备
  - 已信任设备列表
- 高风险内容提醒：
  - 可执行文件
  - 超大文件
  - 批量文件

**预期收益：**
- 降低误收内容风险。
- 提升首次传输时的主观安全感。
- 为后续“最近设备”“可信设备”做基础铺垫。

## P2：把一次性工具做成日常工具

**周期：** 1.5 到 2 个月

**目标：** 降低每次使用 Toss 都要重新建房、重新输入代码的摩擦。

**重点能力：**
- 持久设备名
- 最近设备列表
- 常用设备置顶
- 一键重连上次设备
- 接收历史持久化
- 收件箱式接收列表
- 更清晰的下载状态与重名文件处理

**预期收益：**
- 提升重复使用率。
- 缩短第二次及之后的连接准备时间。
- 让 Toss 从“临时传一下”进入“经常拿来传”。

## P3：补强复杂网络下的可靠性

**周期：** 2 到 3 个月

**目标：** 让 Toss 在弱网、复杂 NAT、企业网络环境下更可预期。

**重点能力：**
- 更友好的网络诊断：
  - 同网段不可达
  - NAT 受限
  - Relay 模式启用中
- 自动 fallback 策略
- 大文件断点续传
- 更明确的失败恢复建议

**预期收益：**
- 提升复杂网络场景成功率。
- 降低用户对“为什么连不上”的困惑。
- 让 Toss 在大文件场景下更可靠。

## P4：构建部署灵活性与团队使用场景

**周期：** 3 到 6 个月

**目标：** 从个人工具扩展到团队、内网和自托管场景。

**重点能力：**
- 自托管 signaling 方案
- LAN-first 模式
- 面向团队/内网的部署文档
- 更清晰的安全边界说明与运维建议

**预期收益：**
- 缩小与 LocalSend、Warpinator 一类产品在“离线与内网独立性”上的差距。
- 让 Toss 更适合对公网依赖敏感的团队环境。

## P5：明确长期产品形态

**周期：** 6 个月以后

**目标：** 决定 Toss 继续深耕浏览器优先体验，还是延伸到轻量原生能力。

**方向 A：浏览器优先**
- 强化零安装、即开即用、分享即发。
- 深耕 PWA 能力与跨平台一致性。

**方向 B：轻原生壳**
- 补后台接收
- 补系统保存目录
- 补文件夹传输
- 补常驻能力

## 建议的投资顺序

资源有限时，建议按以下顺序投入：

1. 接收确认 + 可信设备
2. 最近设备 + 收件箱式接收体验
3. 自动 fallback + 网络诊断
4. 自托管 / LAN-first

## 一句话总结

短期把 Toss 做得“更敢用”，中期做得“更顺手”，长期做得“更独立、更可靠”。
