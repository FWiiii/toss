# Toss UI 系统

Toss 的界面以清晰、轻量和可信为原则：让设备连接、传输进度与安全信息一眼可见，同时避免装饰影响任务效率。

## 设计基础

- 色彩使用 OKLCH CSS 变量；品牌强调色来自 `--accent`，状态色使用 `--success`、`--info`、`--warning` 与 `--destructive`。
- 浅色与深色主题共享同一组语义类名。新增界面优先使用 `bg-background`、`bg-card`、`text-foreground`、`text-muted-foreground` 和 `border-border`。
- 间距按 4px 基准，面板使用 `rounded-2xl`，输入和按钮保持足够的触控尺寸。
- 面板通过 `panel-surface` 获得统一边框与低对比度阴影；不要在单个组件中重复定义主题色值。

## 精简布局规则

- 默认只保留当前任务需要的标题、状态和主操作；解释性文案优先放入展开区或对话框。
- 传输面板的收件记录入口与面板标题共用一行，不再额外占用独立导航行。
- 房间卡片与传送输入区使用紧凑间距；房间代码、连接状态、发送文本、文件和剪贴板操作必须保持可见。
- 共享屏幕、清空记录、连接诊断和安装提示属于次要入口，使用更多菜单、展开区或低占位提示呈现。
- 精简不能隐藏安全警告、风险文件二次确认、房间代码或必要的连接错误信息。

- 连接详情只展示连接类型、延迟、速度和加密状态；解释性说明不常驻，低频的会话指纹保留在展开信息中。
- 设置面板优先展示主题、提醒和必要连接开关；设备信任管理作为折叠的低频配置，不与主要设置抢占注意力。

## 组件与交互

- 优先扩展已有 `components/ui/` 基础控件，不新增没有实际使用场景的包装层。
- 对话框使用 Radix Dialog，保留标题、描述、Escape 关闭、焦点圈定与关闭后的焦点恢复。
- 状态不能只靠颜色表达；配合文字、图标和 `role="status"` / `role="alert"`。
- 可交互控件必须有可见焦点态、明确名称和足够触控区域；表单控件通过 label 或 `aria-label` 关联说明。
- 文件传输保留方向、类型、进度和结果差异；接收历史按需分批呈现，展开详情需通过键盘可操作。

## 动效与主题

- 复用 `delight-*` 动效类和 `--duration-*` 令牌，动效优先使用 opacity 与 transform。
- 全局 `prefers-reduced-motion: reduce` 会停用非必要动画与过渡；持续状态仍需通过静态文字可辨识。
- 新增颜色使用主题变量而非固定浅色值；图片、二维码等媒体可使用独立的高对比背景以保证可读性。

## 验收清单

- 桌面与窄屏布局无横向溢出，交互元素有明确 hover、focus、disabled 状态。
- 浅色、深色主题下文字、状态图标、边框与弹窗都清晰可辨。
- 键盘可完成对话框、筛选器、折叠区和输入区操作；屏幕阅读器可获取动态状态。
- 系统减少动态效果时，页面仍能提供完整状态信息与操作反馈。
